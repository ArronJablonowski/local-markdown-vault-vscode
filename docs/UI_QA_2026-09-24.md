# Human-workflow UI QA — September 24, 2026

## Scope and method

Tested on macOS with VS Code 1.139.0 using disposable profiles and notes. Native
tests drive actual workbench/webview keyboard and pointer events and verify saved
Markdown bytes. Browser tests use the shipped webview bundles with a simulated
host; they supplement rather than replace native filesystem and clipboard tests.
Personal notes and the user's settings were not used as test fixtures.

Three new native journeys start with empty notes and type character by character:

- A planning session with headings, emphasis, highlights, nested bullets,
  Tab/Shift+Tab, task continuation, a folding warning, a Python fence, repeated
  Enter to leave the fence, and a final paragraph. Mouse actions toggle a task,
  fold the callout, and copy the exact code through the system clipboard.
- A research notebook with YAML properties, inline math, a footnote, a price
  table, Mermaid, and draw.io XML. After typing, the journey edits a property and
  a rich-text table cell, adds a table row, and verifies the resulting file.
- Long natural-language bullets, including a Tab-indented child. The test
  measures each visual line's first character to confirm hanging alignment and
  verifies that presentation does not change the saved Markdown.

## Defects reproduced and fixed

1. **Enter could trap the caret in a newly typed code block.** The editor inserts
   a closing fence with blank padding while typing. The escape command previously
   required that fence to be immediately after the current blank line. It now
   scans only consecutive blank lines, within the existing scan bound, and still
   verifies the closing fence. Actual code is never skipped or removed. Added
   unit, browser keyboard, and native typed-note regression coverage.
2. **Sidebar settings could appear to revert.** A workspace override took
   precedence over changes written only to user settings. The sidebar now updates
   an existing workspace override; otherwise it updates the user preference.
   The native test changes every option in all five dropdowns and proves that a
   workspace-level whitespace override can be changed from the sidebar.
3. **A large external replacement could close Find/Replace.** Full host snapshots
   replaced the editor state and discarded its search panel. The panel now
   retains its query, options, replacement text, expanded state, focus, and input
   caret. Three browser regressions cover both input fields and editor focus;
   the native large-paste/external-replacement workflow checks the real host path.
4. **Rapid Live Preview mutations could race native disk saves.** A loaded native
   run reproduced disk content one character behind the open large document.
   The host now settles the preceding save before applying an edit, rechecks
   session/version validity after waiting, and drains the new save before
   acknowledging that batch. Controlled-promise unit tests enforce the ordering
   and reject delayed edits after a close or independent document change. Native
   tests compare exact disk bytes after typing, paste, undo, and file switches.

No dependency, resource-policy, protocol-limit, filesystem-boundary, or network
permission was relaxed for these fixes.

## Requested list-wrap improvement

Markdown Live Preview now measures each visible list prefix and applies hanging
indentation: wrapped text aligns with the first content character after the
bullet, number, or task checkbox. Nested lists and callout lists retain their
existing depth and panel alignment. Measurements adapt to resizing, source
reveal, Tab/Shift+Tab, and theme changes without editing document content.

Nine browser cases cover editing/locked modes, three themes, multiple pane
widths, inline formatting, callouts, and removing/retyping a bullet. A native
typed-note test checks the rendered geometry and exact saved bytes. This change targets the extension's
Markdown Live Preview renderer; it does not replace VS Code's native editors.

## Verification results

- 1,034 unit tests in 100 files passed.
- 446 browser interaction/rendering tests passed, including the nine new list
  wrapping cases and three search-panel resynchronization cases.
- 32 focused native VS Code workflows passed in the final complete run.
- All 15 native menu/dialog/settings groups passed outside the extension-test
  host, including trash confirmation/cancellation and persisted setting values.
- 96 general integration tests passed; 18 mode-specific tests are intentionally
  pending in that runner and run in their dedicated restricted/cache/VSIX jobs.
- All four restricted-workspace checks and both cache-restart phases passed.
- All 15 packaged-extension checks passed across trusted, restricted, and
  disabled modes. The VSIX passed archive/content verification.
- US English and dependency-policy checks passed. npm reported zero known
  advisories across 797 locked dependencies; this does not prove there are no
  undisclosed dependency vulnerabilities.

The rebuilt `0.2.0` VSIX was installed in the local VS Code app. Installed file
contents were compared against the package; existing windows must reload to use
the new extension runtime. The installer checksum is recorded in
[`releases/SHA256SUMS`](../releases/SHA256SUMS).

The stress runs compare saved file bytes, not just the presence of a dirty-tab
indicator. An initial loaded run exposed the save-ordering issue above; it was
not dismissed as a flaky test. The final full native run also passed the complex
note viewport/diagram walkthrough after hanging-indent height measurements were
made to refresh CodeMirror's viewport map.

## Reproduction

```sh
npm ci
npm test
npm run test:e2e
npm run test:integration:focused
npm run test:ui:native
```

Run the two native UI commands separately; simultaneous native windows compete
for keyboard focus. `test:ui:native` creates a temporary vault/profile and records
its report and screenshots under `test-results/human-native-ui/`. Its trash tests
move only its disposable fixtures to the operating system trash. VS Code's
extension-test host intentionally refuses modal confirmations, so those dialogs
are tested in a separate development window instead.

## Limits

This pass does not claim to cover every possible Markdown combination, certify
Windows/Linux, perform a fresh Obsidian side-by-side comparison, or replace human
VoiceOver review. OS-native file-manager dialogs and shell integration are not
part of the automated coverage. VS Code's own Settings UI can re-render while a
value is being saved; tests wait for persistence and revisit rows before checking
their displayed values.

The preexisting concurrent-writer recovery limitation in
[the code QA report](CODE_QA_2026-09-24.md#limits-and-follow-up) remains: independent
editors are not a lossless conflict-merging system. Passing normal autosave tests
does not prove power-loss durability or safe simultaneous edits from two writers.
