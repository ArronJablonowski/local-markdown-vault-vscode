# Extensive QA review — September 22, 2026

## Scope and environment

Review of Local Markdown Vault 0.2.0 starting at commit `54e2301`, followed by
the fixes in this report. Desktop tests use VS Code 1.138.0 on macOS 27.0,
Apple M4, 24 GiB memory. Browser tests mount the extension's real editor bundle
and CSS in Chromium. The available build runtime was Node 26.8.2; `.nvmrc`
recommends Node 24, which was not separately rerun during this pass.
Desktop tests use separate profiles and disposable vaults;
the owner's notes and active VS Code window are not used as test data.

This is broad functional and security-regression QA, not proof that every
possible interaction is correct. No new live Obsidian comparison or Windows or
Linux desktop run was performed during this pass.

## Reproduced and corrected defects

### 1. Native table Cut could delete an unrelated paragraph

A mouse drag selected `Alpha` in a rendered table, but Cut used CodeMirror's
older caret position and copied/deleted `Before` above the table. This was a
real data-integrity bug. The new regression failed before the fix.

Native rendered selections now have their own guarded Cut/Delete path. Plain
text maps to verified source spans; surrounding table syntax and other cells
remain intact. The insertion caret follows the deletion. Whole-table Cut
copies Markdown and removes the table as one editor transaction. Locked mode
copies without deleting. Existing host synchronization, automatic save, and
undo remain the persistence boundary; no separate filesystem write path was
introduced.

Partially selected rich cell markup cannot always be mapped safely to source.
Those ambiguous selections are deliberately non-destructive. Click the cell
to edit its Markdown before cutting part of bold text or a link. Copying the
rendered selection remains available.

### 2. Locked tables could still present editable cells

Although the transaction filter rejected changes, a table cell could acquire
its own `contenteditable` attribute and display temporary changes. Cell editing
now checks the current locked state before entering editing, including mouse
and F2 paths. Keyboard focus remains usable without revealing stale source or
allowing phantom edits. The original regression failed before the fix.

### 3. Repeated Enter could remain inside an unfinished code fence

At the end of a note, an opening fence without a closing fence kept subsequent
text inside code even after repeated Enter. On a final blank code line, Enter
now inserts a matching closing fence and moves to a normal line. Command/Ctrl+
Enter can close and exit the same top-level unfinished block. Code is preserved;
backticks, tildes, and longer fences retain the opener's delimiter.

A single Enter after nonempty code still continues the code. Nested unfinished
fences are not auto-closed because their quote/list prefixes require separate
handling; enter their closing fence explicitly. Tests cover this safety limit.

### 4. One Undo/Redo shortcut could execute twice

The real system clipboard round-trip exposed a second integrity issue: after
Cut followed by Paste, one Undo reverted both operations instead of only Paste.
Document-change tracing confirmed both transitions. VS Code's webview wrapper
forwards bubbled keyboard shortcuts even when the event is default-prevented,
so the extension's own ordered undo request was followed by a second workbench
undo command.

Handled Undo/Redo bindings now stop propagation as well as preventing the
browser default. The host remains the sole undo stack. Browser regressions
check that no duplicate shortcut reaches the enclosing window in editing or
locked mode; the real desktop regression checks individual Cut/Paste undo and
redo steps and their autosaved file bytes.

The same forwarding problem also let the bold shortcut hide VS Code's sidebar.
Owned formatting and Find shortcuts now stop propagation when handled.
Locked document content is explicitly keyboard-focusable so its guarded
shortcuts work after clicking text, not only while an editable caret exists.

  Restricted Mode checks passed.
- Final packaged VSIX runs: nine trusted, five restricted, and one disabled-
  extension check passed. Environment-specific cases are skipped in the other
  profiles by design.
- Focused actual-desktop run: 17 tests passed, including system clipboard Cut,
  Paste, individual host Undo/Redo steps, and byte-verified automatic save.
- Normal installed-app workflow passed folder/note creation, advanced Markdown
  typing and byte-verified autosave, keyboard bold formatting without toggling
  the workbench sidebar, rename, move with content preservation,
  canceled trash, and confirmed trash of a nonempty disposable folder. It uses

- Unit-only coverage: 57% statements, 62.3% branches, 58.25% functions, and

## Test-driver findings

Some initial failures were automation issues, not product fixes:

- Wait for the native Markdown Editor to finish loading before opening its
  viewing-mode picker; otherwise its startup focus handoff dismisses the picker.
- Bring the workbench to the foreground before typing into quick input, and
  include observed input/focus details when that test fails.
- Native macOS context menus are outside Chromium's DOM. Packaged integration
  tests invoke the same command arguments and interact with the real input
  boxes; they do not claim to click those OS-native menu entries.
- VS Code refuses modal dialogs while running extension tests. The separate
  installed-app workflow runs without extension-test mode and uses VS Code's
  custom dialog setting to test Cancel and confirmed trash.

## Reproduction

Run these from the repository with its supported Node version and dependencies
installed. Desktop runs open isolated test windows; avoid running multiple
desktop suites concurrently because they compete for foreground focus.

```sh
npm run test:all
npm run test:integration:focused
npm run test:performance:filesystem
node scripts/run-vault-ui-qa.mjs
npm run security:dependencies
npm run security:audit
npm run language:verify
```

The installed-app workflow requires the current root-level VSIX from
`npm run package`. It creates only disposable QA files. Confirmed folder trash
is recoverable through the operating system Trash; temporary profiles are
removed after the run.

## Remaining limitations and release gates

- Re-run native Windows/Linux interactions before claiming cross-platform live
  QA completion. This pass executes on macOS only.
- Complete independent VoiceOver and other target-platform screen-reader review.
- VS Code's separate built-in **Markdown Editor** retains the previously
  documented end-of-list editing limitation. These fixes target **Markdown Live
  Preview**, the extension's default, and do not patch VS Code's built-in editor.
- Use the cell's Markdown editor for ambiguous partial rich-text Cut/Delete;
  close nested unfinished code fences explicitly.
- Zero known dependency advisories and passing malicious fixtures do not prove
  absence of vulnerabilities. Continue dependency monitoring and security review
  whenever rendering, message handling, or filesystem behavior changes.
