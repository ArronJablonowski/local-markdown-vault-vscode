## New automated UI checks

- Every option in all five sidebar settings emits its corresponding host request.
- All four per-theme action buttons and New style emit the intended action without
  accidentally applying a theme. These checks use a host stub, not real deletion
  of user themes.
- Keyboard focus survives settings/theme acknowledgments; refreshes do not steal
  focus from unrelated controls. Restricted Mode removes theme mutation controls.
- Underlined and multiline headings render in Editing and Locked modes.
- Mixed callouts unfold/refold using keyboard and pointer controls, preserving
  their table, escaped code pipes, and footnote navigation.
- Table code decodes escaped pipes while ordinary code retains its backslashes.

## Defects fixed

1. Sidebar refreshes rebuilt controls and lost keyboard focus. Stable control
   identities now restore focus without interpolating theme IDs into selectors;
   refreshes also retain scroll position.
2. Setext headings lacked heading styling. Both heading levels and every content
   line of a multiline heading now receive the correct styling.
3. Table code spans displayed the escape slash before a pipe. Decoding is now
   explicitly limited to table contexts, including embedded tables and cell edits.
   This follows the [GFM table specification](https://github.github.com/gfm/#tables-extension-).
4. Reference-style links remained literal. A bounded parser-backed lookup now
   resolves full, collapsed, shortcut, and image references through existing
   navigation/media controls. Undefined labels and footnotes are not converted
   into links. Definitions inside code are ignored.
5. Escaped punctuation displayed the backslash. Parser-confirmed escape markers
   now hide outside source editing; literal code keeps its backslashes.
6. A repeated mixed-callout table-edit test intermittently crashed when a redraw
   fired focusout during an editor update. Focus-loss saves now run after that
   update; existing commit-once and stale-source guards remain in place.

## Limits and coverage distinctions

This is not proof that every possible Markdown document or every platform is
correct. The full existing suite supplements this pass with vault operations,
diagrams, tables, search, accessibility, and hostile-input checks. Its repeated
tests are regression coverage, not presented as new scenarios.

Native Windows/Linux, full screen-reader sessions, destructive operations on real
themes, external URL launches, and every VS Code settings-page combination were
not manually exercised. Theme action-message coverage does not prove completion
of host-side dialogs. Built-in Markdown Preview renders wikilinks and callout
markers literally; that mode limitation is now documented in the README.
