# Table QA — September 23, 2026

Tested on macOS with Chromium browser tests and the packaged extension in VS Code 1.139.0.

## Coverage

- Generated tables with 1, 3, 12, and 30 columns, up to 100 rows (3,000 cells), at 400px and 900px viewport widths.
- Multiple long tables in one note, independent sticky headers, horizontal scrolling, and resizing between 400px and 1000px, with default and Obsidian-style CSS.
- Bold text, links, inline code, Unicode, alignment, empty cells, and safe HTML line breaks.
- Cell editing, cancel, Enter and Tab navigation, saving far-right cells, and source view with pending edits.
- A visible source button on each table, scoped to that table, in both Editing and Locked modes.
- Existing regression coverage for structural controls, sorting, mouse selection, copy/cut/delete, locked editing, keyboard access, and hostile Markdown.

## Fixes

1. Saving a wide-table cell reset horizontal scrolling. Restore the offset after the replacement widget establishes its scroll container; apply the same handling to structural edits.
2. Tab from an unchanged header could target a decorative sticky-header cell. Remove editing metadata from the header copy and scope keyboard navigation to the real table.
3. Add a compact, always-visible `</>` button above every rendered table, with an accessible name and tooltip. Pending cell edits are committed before source is shown; Locked mode remains read-only.

## Validation

- 975 deterministic unit tests passed.
- 254 browser tests passed, including 16 new table QA cases.
- The installable package passed content verification and clean-profile VS Code smoke tests.
- A sidebar smoke-test failure was traced to forward-only keyboard traversal toward an earlier control. The harness now chooses Tab or Shift+Tab toward the target and records visited controls on failure.

These checks cover the tested fixtures and interactions; this run does not constitute live Windows/Linux testing or a new full security audit.
