# Code QA review - September 24, 2026

## Scope

Reviewed the host/webview message protocol, edit queue, document versions and
offsets, autosave lifecycle, undo/redo dispatch, rendering refreshes, resource
clients, filesystem containment and trash/move checks, and index/cache bounds.
Ran the broader automated suites for editor modes, lists, tables, callouts,
diagrams, links/embeds, properties, clipboard, vault management, and malicious
Markdown. Native desktop execution was on macOS using disposable fixtures.

## Confirmed fixes

1. **Large edits could stop saving.** The renderer sent a single batch even when
   it exceeded the 1 MiB inserted-text or 1,000-change protocol limits. The host
   rejected it, leaving the renderer waiting for an acknowledgment. Pending edits
   now drain in bounded, acknowledged batches. Splitting preserves UTF-16 offsets
   and Unicode surrogate pairs. Later typing composes onto the remaining edits.
2. **Large external replacements could leave a stale preview.** The host sent
   oversized incremental patches that the renderer correctly rejected. Oversized
   patches now use the existing bounded full-document snapshot path instead.
3. **Valid undo and highlighting ranges could be rejected after typing.** The
   renderer's validator retained the original document length after local edits.
   It now tracks the outgoing edit batches, allowing valid ranges in newly added
   text while retaining bounds checks.
4. **Undo/redo could overlap an automatic save.** Desktop testing reproduced a
   changed open document with old disk content during repeated undo. History
   operations now settle pending autosaves before and after the native command.
   The command rechecks that its original panel is active after waiting, so a
   delayed undo cannot run against another tab.

No message-size limits, path restrictions, CSP rules, or network permissions were
relaxed. Emoji and table behavior from the prior fixes remains covered.

## Regression evidence

- Large ASCII, CJK, and emoji replacements round-trip through validated batches.
- More than 1,000 disjoint changes split correctly and retain later typing.
- Browser paste and subsequent typing reconstruct the exact expected document.
- Native clipboard paste, later typing, and a large external replacement are
  checked against actual disk bytes and visible preview content.
- Host undo after extending a document remains visible in the renderer.
- Autosave flushing waits for an in-flight save and persists newer dirty edits.
- The complete focused desktop suite passed 26 scenarios, including large-file
  undo, clipboard operations, external edits, vault moves, and hostile content.
- 1,030 unit tests and 431 browser tests passed. General VS Code integration
  passed 96 tests. npm reported zero known advisories across 797 dependencies;
  dependency policy validation passed.
- Both cache restart phases, four restricted-workspace tests, and all 15
  packaged-extension checks passed. The rebuilt VSIX was installed locally.

The desktop tests were corrected to assert saved bytes rather than requiring a
transient dirty flag to remain visible. External-writer tests now wait for the
native save operation to finish before replacing the file. Cleanup also waits
for native saves before removing disposable fixture directories.

## Limits and follow-up

Unit coverage is approximately 57.65% of lines; browser and native interaction
coverage is additional, but does not make this an exhaustive proof. This pass
does not certify Windows/Linux behavior, power-loss durability, or freedom from
all vulnerabilities. Advisory results are a point-in-time check, not an audit
of every dependency's source.

Simultaneous edits from independent editors are not merged: the existing protocol
favors the host snapshot when document versions conflict. Lossless recovery of
unacknowledged local changes during such a conflict remains a follow-up; do not
treat normal autosave tests as proof that concurrent writers are safe. A future
change should preserve a local recovery copy before a conflict-driven reset.
